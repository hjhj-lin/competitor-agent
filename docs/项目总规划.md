## 二、项目业务场景

用户输入一个目标公司名（如"字节跳动"），系统启动多个 Agent 协作：

```
用户输入 "字节跳动"
    ↓
采集 Agent → 从公开渠道采集竞品信息（产品动态、融资、舆情等）
    ↓
分析 Agent → 提炼关键指标，对比竞品优劣势
    ↓
报告 Agent → 生成结构化竞品分析报告
    ↓
审核 Agent → 交叉校验，标注数据来源和置信度
    ↓
用户收到一份完整的竞品分析报告
```

每个 Agent 内部采用 **ReAct 模式**（思考→行动→观察循环），不是一次性调用，而是：

```
Agent 收到任务
    ↓
思考（Thought）：我需要先搜索字节跳动的最新产品动态
    ↓
行动（Action）：调用"搜索工具"
    ↓
观察（Observation）：得到搜索结果
    ↓
思考（Thought）：我还需要查一下融资信息
    ↓
行动（Action）：调用"搜索工具"
    ↓
观察（Observation）：得到融资数据
    ↓
思考（Thought）：信息足够了，我可以输出结论了
    ↓
输出最终结果
```

| 层       | 技术            | 职责                            | 人话          |

| 接口层   | Controller      | 接收请求、参数校验、返回响应    | 前台接待员    |

| 编排层   | AgentPipeline   | Agent 串行编排、重试、降级      | 项目经理      |

| 模型层   | Spring AI       | 模型调用、Prompt 模板、对话记忆 | AI 大脑       |
| 数据层   | Mapper + MySQL  | 业务数据 CRUD + 全文检索        | 仓库 + 档案室 |

### Service 层 vs Pipeline 的边界约定

| 归属           | 管什么   | 举例                                         |
| -------------- | -------- | -------------------------------------------- |
| **Service 层** | 业务规则 | 用户能不能创建任务？任务名是否为空？权限校验 |
| **Pipeline**   | 执行顺序 | 先跑采集再跑分析？失败了重试还是跳过？       |

**原则：Service 不写编排逻辑，Pipeline 不写业务规则。**

## 四、Agent 框架设计（核心亮点）

### 设计原则

> **不造轮子，不过度抽象。** 4个Agent、4-5个工具，不需要DAG、不需要反射注册、不需要权限控制注解。
> 用最简单的代码解决实际问题，面试时讲清"为什么这样设计"比"设计多复杂"更有价值。

### 4.1 核心接口（3个类，~70行）

```java
public interface Agent {
    String getName();
    String getDescription();
    AgentResult execute(AgentContext context);
}

public class AgentContext {
    private String taskId;
    private Map<String, Object> inputs;
    private Map<String, Object> outputs;   // ConcurrentHashMap，防并发
    private List<Message> history;
}

public class AgentResult {
    private boolean success;
    private Map<String, Object> data;
    private String error;
    private double confidence;
}
```

### 4.2 Pipeline 编排（1个类，~60行，替代DAG的300行）

```java
public class AgentPipeline {
    private final List<AgentStep> steps = new ArrayList<>();

    public AgentPipeline add(Agent agent, int maxRetries, boolean skipOnFailure) {
        steps.add(new AgentStep(agent, maxRetries, skipOnFailure));
        return this;
    }

    public PipelineResult execute(AgentContext context) {
        for (AgentStep step : steps) {
            AgentResult result = executeWithRetry(step, context);
            if (!result.isSuccess() && !step.skipOnFailure) {
                return PipelineResult.fail(step.agent.getName(), result.getError());
            }
            context.getOutputs().put(step.agent.getName(), result);
        }
        return PipelineResult.success(context);
    }

    private AgentResult executeWithRetry(AgentStep step, AgentContext context) {
        for (int i = 0; i <= step.maxRetries; i++) {
            try {
                return step.agent.execute(context);
            } catch (Exception e) {
                log.error("[Agent失败] agent={} retry={}/{} error={}",
                    step.agent.getName(), i, step.maxRetries, e.getMessage());
            }
        }
        return AgentResult.fail("重试" + step.maxRetries + "次后仍失败");
    }
}

// 使用：在配置类里组装
@Bean
public AgentPipeline competitorAnalysisPipeline() {
    return new AgentPipeline()
        .add(collectAgent, 2, false)     // 采集：重试2次，失败不跳过
        .add(analysisAgent, 2, false)    // 分析：重试2次，失败不跳过
        .add(reportAgent, 1, false)      // 报告：重试1次，失败不跳过
        .add(reviewAgent, 1, true);      // 审核：重试1次，失败跳过（降级）
}
```

**为什么不用 DAG？** 4个Agent之间有严格依赖（采集→分析→报告→审核），不存在并行和条件分支的需求。DAG 是在解一个不存在的问题。如果未来需要并行，再扩展也不迟。

### 4.3 工具层：直接用 Spring AI @Tool（不需要自研注解）

```java
@Component
public class SearchTool {
    @Tool(description = "搜索互联网信息，返回搜索结果")
    public String search(String query) {
        // 调 Tavily API
    }
}

@Component
public class WebExtractTool {
    @Tool(description = "提取网页正文内容")
    public String extract(String url) {
        // 用 Jsoup 提取
    }
}
```

**为什么不用 @AgentTool？** 4-5个工具，手动在Agent里注入就行，不需要反射扫描自动注册，不需要权限控制注解。Spring AI 的 @Tool 已经解决了"AI怎么调工具"的问题，不需要再包一层。

**每个Agent自己注入需要的工具：**

```java
@Component
public class CollectAgent implements Agent {
    private final SearchTool searchTool;       // 采集Agent用搜索
    private final WebExtractTool extractTool;   // 采集Agent用网页提取
    // 不注入 ReportGenerateTool，因为采集Agent不需要生成报告
}
```

### 4.4 ReAct 循环（~150行，真正的核心逻辑）

```java
public class ReActExecutor {
    private static final int MAX_ITERATIONS = 10;

    public AgentResult execute(Agent agent, AgentContext context) {
        int iteration = 0;
        while (iteration < MAX_ITERATIONS) {
            iteration++;

            String thought = aiService.chat(buildPrompt(context));

            if (isFinalAnswer(thought)) {
                return AgentResult.success(extractAnswer(thought));
            }

            ToolCall toolCall = parseToolCall(thought);
            String observation = toolService.execute(toolCall);
            context.getHistory().add(Message.toolResult(observation));
        }

        return AgentResult.fail("超过最大循环次数 " + MAX_ITERATIONS);
    }
}
```

### 4.6 Agent 安全机制

| 机制                | 值                          | 作用                          |
| ------------------- | --------------------------- | ----------------------------- |
| ReAct 最大循环次数  | 10 次                       | 防止 AI 死循环                |
| 单次 AI 调用超时    | 30 秒                       | 防止模型卡住                  |
| Agent 总执行超时    | 5 分钟                      | 防止任务永远跑不完            |
| 工具执行超时        | 10 秒                       | 防止外部 API 卡住             |
| Prompt 输出格式约束 | JSON Schema                 | 强制 AI 按格式返回，容错解析  |
| 单 Agent 重试       | 最多 2 次                   | AI 调用本身不稳定，重试很常见 |
| 降级跳过            | 审核Agent失败不影响报告输出 | 标注"未经审核"即可            |

### 4.7 成本控制

| 策略               | 值                  | 说明                                |
| ------------------ | ------------------- | ----------------------------------- |
| 单任务 AI 调用上限 | 20 次               | 超过直接终止，防止烧钱              |
| 用户每日任务限额   | 5 个                | 防止滥用                            |
| 采集结果缓存       | 24 小时（Caffeine） | 同一公司名不重复搜索                |
| Prompt 精简        | -                   | 系统 Prompt 控制长度，按 token 计费 |

## 十、面试核心话术（项目完成后你能讲什么）

### 第一梯队：必讲亮点

1. **"我实现了 ReAct 模式"** —— Agent 采用思考→行动→观察循环，不是一次性调用，能根据中间结果动态调整策略。带最大循环次数和超时保护，防止死循环。用 Spring AI Structured Output 强制 AI 按格式返回
2. **"我设计了 Pipeline 编排"** —— 支持重试和降级，审核Agent失败不影响报告输出。没有过度设计成 DAG，因为4个Agent之间有严格依赖，串行 Pipeline 就够了
3. **"我基于 Spring AI Tool Calling 实现了工具调用"** —— Agent 能自主选择并调用搜索、提取等工具。用 Spring AI 原生 @Tool 注解，不重复造轮子

### 第二梯队：加分亮点

4. **"我做了成本控制"** —— 单任务 AI 调用上限、用户每日任务限额、采集结果缓存（Caffeine），防止 API 费用失控
5. **"我设计了任务状态机"** —— PENDING→RUNNING→COMPLETED/FAILED，支持异步执行和进度查询
6. **"我实现了 Agent 执行记录"** —— 每个 Agent 的 ReAct 循环每轮 thought/action/observation 都落库，可追溯、可调试

### 第三梯队：锦上添花

7. **"我实现了 SSE 流式响应"** —— AI 回复逐字推送到前端，用户体验像 ChatGPT
8. **"我集成了 Tavily 搜索 API"** —— 专为 AI Agent 设计的搜索接口，Agent 能实时获取互联网信息
9. **"我做了统一异常处理和响应格式"** —— 所有接口返回 `{code, message, data}`，全局捕获异常
10. **"我做了结构化日志"** —— 关键节点用 `[标签]` 格式打日志，方便 grep 搜索和问题排查

### 面试追问预演

| 追问                                   | 回答                                                                                                                         |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| "ReAct 循环里 AI 不按格式返回怎么办？" | 用 Spring AI Structured Output 强制 JSON 输出 + 正则容错提取                                                                 |
| "为什么不用 DAG 编排？"                | 4个Agent之间有严格依赖（采集→分析→报告→审核），不存在并行和条件分支的需求。DAG 是在解一个不存在的问题，Pipeline 更简单更够用 |
| "为什么不用 LangChain4j？"             | Spring AI 和 Spring Boot 同生态，集成更自然；工具调用用 Spring AI @Tool 就够了，不需要再包一层                               |
| "Agent 失败了怎么办？"                 | Pipeline 支持重试（最多2次）和降级（审核Agent失败跳过，标注"未经审核"）                                                      |
| "Agent 执行记录表数据量大了怎么办？"   | 按月分表，或定期归档到冷存储                                                                                                 |
